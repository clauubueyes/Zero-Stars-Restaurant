# M1: jugador en primera persona y restaurante greybox

Fecha: 2026-10-06. Rama: `feature/player-controller`, desde la foundation aprobada
`a6882ba`. Estado: implementado, pruebas automatizadas pasadas, aceptación con
teclado/ratón y revisión visual pendiente del usuario. No se implementó M2.

## Abrir y probar

1. Usar **Unity 6000.5.3f1**. Esperar la importación/compilación; si el Editor ya
   está abierto, usar **Assets > Refresh** si es necesario y revisar Console.
2. Abrir `Assets/_Project/Scenes/PrototypeRestaurant.unity` en modo Single desde
   Project (doble clic). Guardar otras escenas si Unity lo solicita. No cargar
   simultáneamente SampleScene, que tiene otra cámara y AudioListener.
3. Pulsar Play y enfocar la pestaña **Game**. Si el cursor queda libre al cambiar
   de pestaña, hacer clic izquierdo dentro de Game para capturarlo.
4. Moverse con **WASD**, mirar con **ratón**, saltar con **Espacio**. No hay sprint,
   agacharse, interacción, inventario ni acciones de restaurante.
5. Caminar contra las cuatro paredes exteriores, el mostrador y el bloque alto.
   El jugador no debe atravesarlos. Probar también desplazamiento en diagonal:
   no debe ser más rápido que avanzar en línea recta.
6. Saltar y aterrizar sin pulsar movimiento. No debe haber salto en el aire.
   El escalón bajo permite comprobar stepOffset y descenso; el bloque alto no debe
   poder atravesarse ni subirse con el salto estándar. La cápsula, y no la cámara,
   determina la colisión del jugador.
7. Mirar arriba/abajo: la cámara debe detenerse antes de invertirse (±85°).
8. Pulsar **Escape**: cursor visible/libre, sin movimiento voluntario ni mirada.
   Hacer clic izquierdo en Game: vuelve el control. Si se libera durante un salto,
   la gravedad sigue activa y el jugador aterriza.
9. Cambiar el foco fuera de Unity: se libera el cursor. Volver y hacer clic en
   Game para recuperar control. Detener Play también libera el cursor.
10. Entrar/salir de Play al menos dos veces: mismo spawn y velocidad, sin input
    duplicado ni errores de Console. Repetir captura/liberación varias veces.

Esta aceptación manual comprueba experiencia, dispositivos/foco reales y render.
Los tests automatizados no sustituyen esos pasos.

## Configuración y límites

En `Player`:

| Componente / campo | Valor inicial | Función |
| --- | --- | --- |
| FirstPersonMotor / Move Speed | 4 m/s | Velocidad horizontal, normalizada en diagonal. |
| FirstPersonMotor / Jump Height | 1 m | Salto simple; valor 0 lo desactiva. |
| FirstPersonMotor / Gravity | -20 m/s² | Gravedad explícita. |
| FirstPersonMotor / Terminal Fall Speed | 40 m/s | Límite de caída. |
| FirstPersonController / Mouse Sensitivity | 0.1° por unidad de delta | Sensibilidad del ratón. |
| FirstPersonController / Pitch Limit | 85° | Límite arriba/abajo. |
| CharacterController | altura 1.8 m, radio 0.3 m | Cápsula física sin Rigidbody ni modelo. |
| CharacterController / Step Offset | 0.25 m | Escalones bajos. |
| CharacterController / Skin Width | 0.03 m | Margen de colisión. |
| PlayerCamera | altura 1.65 m, FOV 75°, near 0.05 m | Cámara hija, configurable en Inspector. |

La escena tiene interior de 14 × 12 m, suelo, cuatro paredes, división parcial de
cocina y volúmenes de mostrador, mesa, superficie de trabajo, escalón y bloque
alto. Todo es Cube de Unity con BoxCollider y tres materiales URP/Lit de color,
sin texturas. No tiene techo para facilitar iluminación y lectura del greybox.
`DevelopmentSun` y luz ambiente permiten ver el prototipo; no representan
suministro eléctrico ni implementan un sistema de electricidad.

El controlador reutiliza el asset de input existente mediante una instancia de
runtime. Solo habilita Player/Move, Player/Look y Player/Jump y filtra el grupo
Keyboard&Mouse. No activa Interact, Attack, UI ni gamepad. Escape y clic izquierdo
son acciones locales de cursor. No se modificaron bindings, el asset compartido
ni la configuración global de input.

No hay saldo, HUD, comida, clientes ni economía: esos sistemas siguen pendientes.
No se modificó SampleScene ni la lista de escenas de Build Settings. Para abrir
y probar M1 basta su asset de escena; no depende de estar en esa lista.

## Reconstruir el greybox

1. Detener Play. Guardar o cerrar escenas sin nombre (Untitled).
2. Cerrar `PrototypeRestaurant`; se puede abrir `SampleScene` u otra escena
   guardada. Las otras escenas abiertas pueden mantenerse, incluso con cambios.
3. Ejecutar **Zero Star Restaurant > M1 > Rebuild Greybox Scene**.
4. Confirmar la sustitución de la escena guardada cuando el diálogo lo solicite.
5. Volver a abrir `PrototypeRestaurant` desde Project.

Se reproducen jerarquía, dimensiones, componentes y referencias desde código.
Los tres materiales se reutilizan si ya existen y no se sobrescriben sus colores
personalizados. Cambios manuales en la escena se pierden si se confirma reconstruir;
el generador no se ejecuta automáticamente al importar o entrar en Play.
Trabaja en una escena aditiva temporal, la guarda y la cierra restaurando la
escena activa anterior. Unity puede asignar otros fileID internos al reconstruir;
los GUID de assets existentes se conservan.

La generación en batch sustituye únicamente la escena inicial Untitled limpia del
Editor batch por SampleScene. En un Editor interactivo, las escenas Untitled
requieren guardarse/cerrarse previamente y no se descartan de forma automática.

## Repetir los tests

Desde **Window > General > Test Runner**, ejecutar las suites
`ZeroStarRestaurant.Tests.EditMode` y `ZeroStarRestaurant.Tests.PlayMode` en sus
pestañas respectivas. Ejecutar PlayMode en el Editor original solo cuando no se
esté jugando y se haya preparado/guardado el trabajo de escena.

Para batch, usar una copia aislada o cerrar previamente el Editor del proyecto
objetivo. Ejemplo de argumentos del Editor instalado, con rutas adaptadas al
equipo y sin `-quit` (el Test Runner termina el proceso):

```text
-batchmode -nographics -projectPath "<copia aislada>" -runTests
-testPlatform EditMode -assemblyNames ZeroStarRestaurant.Tests.EditMode
-testResults "<ruta absoluta>/M1-EditMode.xml" -logFile "<ruta absoluta>/M1EditMode.log"
```

Cambiar EditMode por PlayMode y el nombre del assembly/archivos para el otro modo.
